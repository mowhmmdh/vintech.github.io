مدیریت Incident در قطعی شبکه

در زمان قطعی شبکه، سرعت مهم است اما تغییرات بدون Evidence می‌توانند دامنه مشکل را بیشتر کنند. فرآیند Incident باید همزمان روی بازگردانی سرویس و حفظ شواهد تمرکز کند.

Incident Flow: Detect → Scope → Stabilize → Evidence → Hypothesis → Mitigate → Validate → Root Cause → Document

Scope را سریع مشخص کنید

تعداد کاربران، Segmentها، سرویس‌ها و مسیرهای درگیر را مشخص کنید. یک اختلال محلی را با قطعی سراسری اشتباه نگیرید.

Stabilize قبل از تغییرات بزرگ

اگر Mitigation کم‌ریسکی برای بازگرداندن سرویس وجود دارد، آن را بر اساس شواهد اجرا کنید. از تغییر همزمان چند متغیر در Production پرهیز کنید.

Evidence حفظ کنید

Timestamp، لاگ، Interface Counters، وضعیت Routing، DNS و علائم سمت سرویس را ثبت کنید. این داده‌ها برای تحلیل Root Cause ضروری هستند.

Validation

پس از Mitigation، همان شاخص‌هایی را که برای تشخیص استفاده کردید دوباره بررسی کنید. بازگشت یک Ping به معنی پایان Incident نیست؛ سرویس واقعی باید سالم باشد.

Lessons Learned

پس از Incident، Timeline، Root Cause، اقدامات مؤثر و موارد قابل پیشگیری را ثبت کنید. نتیجه باید به Runbook، Monitoring یا تغییر معماری منجر شود.

جمع‌بندی

Incident Response حرفه‌ای ترکیبی از آرامش عملیاتی، Evidence، تغییر کنترل‌شده و Validation است. هدف فقط رفع قطعی امروز نیست؛ کاهش احتمال و اثر Incident بعدی است.
